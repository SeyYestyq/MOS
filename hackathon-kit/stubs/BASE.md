# Базовый файл — Activity Map (Positive Technologies / Runtime Radar)

> Обязательный текстовый файл сдачи (Мос.Хаб). Заполняют **все трое** перед freeze (Frontend / Backend / Platform).

## 1. О продукте

**Название:** Activity Map (интерактивная карта активности контейнера)  
**Команда:** _указать имена_  
**Задача:** помочь аналитику ИБ быстро восстановить картину происходящего в контейнере по данным Runtime Radar.

**Что умеет прототип:**

- дерево процессов (ppid → pid);
- сетевые соединения;
- хронология / таймлайн событий;
- синхронизация выбора между панелями;
- Incident Summary (карточка для SOC + копирование).

## 2. Стек

- Web: Vite + React + TypeScript + `@xyflow/react` + dagre  
- BFF: FastAPI + Pydantic (OpenAPI)  
- Данные: fixture JSON и/или live Runtime Radar (HTTP)

## 3. Как запустить

```bash
# BFF
cd apps/bff && pip install -r requirements.txt && uvicorn app:app --reload --port 8000

# Web
cd apps/web && npm i && npm run dev
```

Подробнее: `README.md`, демо-сценарий: `docs/DEMO.md`.

## 4. Использование ИИ-инструментов

ИИ разрешён регламентом. Команда указывает инструменты и этапы:

| Инструмент | Этапы |
|------------|--------|
| Cursor (агент) | scaffold web/bff, UI панелей, BFF/fixture, черновики docs |
| _другое_ | _если было_ |

**Ответственность команды:** ключевые архитектурные и продуктовые решения осмыслены нами и объяснимы на защите. Итоговый код проверен на работоспособность.

## 5. Проверка безопасности (ИБ)

Сгенерированный ИИ код просмотрен командой:

- [ ] нет секретов / паролей RR в репозитории;
- [ ] токены и пароли только из env / локального `.env` (не в git);
- [ ] нет небезопасных практик, критичных для демо (открытые секреты в UI и т.п.).

## 6. Ограничения

- Live Runtime Radar зависит от kind/eBPF; при сбое UI работает на fixture (`X-Data-Source: fixture`).
- Прототип хакатона, не production-SDK.
