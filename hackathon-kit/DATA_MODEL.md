# Целевая модель данных (принято)

Источник: ревью напарника + схема «API и dump → один адаптер → снимок → три проекции → общие фильтры».  
Реализует **бэкенд (Денис / напарник по контракту)**. UI (Ангелина) только читает этот JSON. Дамир подаёт оба входа (REST и dump) в **один** адаптер.

Текущие `types.ts` / Go structs — черновик. После посадки модели они должны совпасть; расхождение TS / Go / Markdown запрещено (один тест на фикстуру).

## Поток

```
Runtime Radar API ──┐
                    ├─► один адаптер формата RR
сохранённый dump ───┘
        │
        ▼
валидация, дедуп, время
        │
        ▼
согласованный снимок активности
        ├─ процессы
        ├─ сетевые наблюдения
        └─ события и угрозы
                │
                ▼
        общие фильтры и selection в UI
```

Live и dump после адаптера дают **одинаковые** внутренние события. Ветки не расходятся.

## 1. Идентичность контейнера

Имени пода мало (рестарты, несколько контейнеров).

| Поле | Обязательно |
|------|-------------|
| `cluster` | да |
| `namespace` | да |
| `podName` | да |
| `podUid` | да, если есть в событии |
| `containerId` | да, если есть |
| `containerName` | да, если есть |

Снимок фильтруется по этой четвёрке/пятёрке, не только по `pod` string.

## 2. Процесс и времена

| Поле | Смысл |
|------|--------|
| `execId` | id узла |
| `parentExecId` | id родителя, **если он есть в снимке** |
| `parentStatus` | `known` \| `outside_window` \| `unknown` |
| `startedAt` | старт процесса (Tetragon `start_time`), не первое событие в дампе |
| `exitedAt` | **только** подтверждённый `PROCESS_EXIT`. Нет exit → поле пустое |
| `firstObservedAt` | первое событие этого exec в окне |
| `lastObservedAt` | последнее событие. **Не** значит, что процесс завершился |

Правила дерева:

- ребро только `parentExecId → execId`, оба узла в снимке;
- родитель вне окна → узел с `parentStatus: outside_window`, **без** приклеивания к init ради красивого дерева;
- pid/ppid — подписи, не рёбра.

## 3. Сеть — наблюдения, не «активные сокеты»

История kprobe ещё не список живых сокетов.

| Поле | Смысл |
|------|--------|
| `kind` | `connect` \| `listen` \| `close` |
| `execId` | процесс, который вызвал kprobe |
| `local` | `{ addr, port }` |
| `remote` | `{ addr, port }` (у listen remote может быть пуст) |
| `observedAt` | время события |
| `proto` | tcp/udp |

Источник в сыром RR: `args[].sock_arg` (не `sockaddr_arg` для `tcp_connect` с `type: sock`).  
ClickHouse `runtime_events` этих полей не хранит — адаптер читает REST JSON или dump полного события.

## 4. Угрозы — отдельные сущности

Не только `mitre[]` на узле.

| Поле | Смысл |
|------|--------|
| `id` | id сработки |
| `detectorId` | id детектора RR |
| `severity` | CRITICAL / … |
| `reason` | текст |
| `tactics` | например TA0011 |
| `techniques` | например T1571 |
| `eventId` | ссылка на исходное событие |
| `execId` | процесс |
| `observedAt` | время |

Третья дорожка таймлайна считается по этому списку, не по «процесс покрашен».

## 5. Один проверяемый контракт

- Канон: JSON Schema или Go struct + сгенерированный / сверенный `types.ts`.
- Фикстура `sample-activity.json` проходит один и тот же decode в Go и в TS-тесте.
- `X-Data-Source`: `live` \| `raw` \| `fixture` — после адаптера форма одна.
